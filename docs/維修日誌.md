# RAG Demo 維修日誌

## 2026-07-23 - 日期與星期問題誤走文件檢索

### 現象

- 使用者先詢問 IFRS 17 問題，再追問「那麼今天是星期幾？」。
- Self-RAG 誤判需要文件證據，執行 BM25、Embedding 與 Rerank。
- 最終回答「資料不足，無法確定今天是星期幾」。

### 根因

1. `/api/route` 將最近 IFRS 17 對話與目前問題串成同一段文字，再交給檢索決策器。
2. 決策器受到前一輪的 IFRS 17 關鍵詞影響，將即時日期問題誤判為文件問題。
3. 誤走檢索後，文件回答模式限制只能根據檢索片段作答，因此 system prompt 中的動態日期無法被正常使用。

### 修正

- 路由時將「目前問題」和「對話背景」分開；歷史只用來解析代名詞與省略，不參與目前問題的確定性規則。
- 新增日期、星期與時間意圖判斷，這類問題固定跳過 knowledge base。
- 直接從 `Asia/Taipei` 系統時鐘產生答案，不讓模型推算日期或星期。
- `/api/ask` 增加後端保護，即使收到錯誤的檢索狀態或檢索片段，仍優先使用系統時鐘回答。
- 一般問題改用獨立 system prompt，可直接處理寒暄、基本算術、一般常識、文字解釋、翻譯與格式整理。
- 文件限定規則只保留在 RAG 回答路徑，避免一般問題因缺少檢索片段而被拒答。

### 驗證

- 「那麼今天是星期幾？」在 2026-07-23 回答「今天是 2026 年 7 月 23 日，星期四」。
- 「請問現在幾點？」使用台北時區的請求當下時間回答。
- 帶有 IFRS 17 歷史背景時，日期問題仍判斷為不需要檢索。
- 包含「今天」的真正 IFRS 17 問題不會被誤判成日期查詢。
- 「2 + 2 是多少？」即使前一輪在討論 IFRS 17，仍跳過檢索並交由一般問答路徑。

### 狀態

- 已修復。

## 2026-07-23 - 檢索路由器提前知道語料內容

### 現象

- 前端在判斷是否需要 RAG 前，先把使用者已選文件的標題傳給 `/api/route`。
- 路由 prompt 要求優先使用候選章節詞彙，並以 IFRS / IFRS 17 硬編碼強制進入檢索。
- 這會讓路由器把「資料庫目前有哪些內容」和「問題是否需要外部證據」混為一談，產生先入為主的判斷。

### 根因

1. 檢索路由與資料源選擇被寫在同一個決策節點。
2. Query rewrite 允許從候選文件標題補詞，使改寫結果受目前語料清單污染。
3. Rerank 分數在每次候選集合內正規化；即使所有片段都不相關，排名第一的片段仍可能得到看似不低的分數。

### 修正

- 採 query-only router：檢索前只看目前問題，以及僅用於解析代名詞的對話背景。
- 前端與 `/api/route` 移除 `section_titles`，路由器不再知道文件、標題或章節清單。
- 移除 IFRS / IFRS 17 domain guard；是否檢索改由「可靠回答是否需要外部證據」決定。
- 查詢改寫只能根據問題本身產生自然同義詞。
- 參考 CRAG 與 LangGraph Agentic RAG，在檢索後新增 Evidence Relevance Gate。
- Evidence Gate 使用正規化前的 BM25、Embedding 與 matched terms；證據不相關時停止 grounded generation 並移除引用。
- Grounded generation 不再帶入舊助理回答，只保留最近使用者問題供代名詞解析，避免前一輪錯誤文字污染新回答。
- 頁面初始化完成前暫停送出與新增對話，避免歷史對話尚在載入時把新問題寫進舊會話。
- 研究與架構決策記錄於 `docs/adaptive-rag-routing-research.md`。

### 驗證目標

- 路由請求與 prompt 不包含所選文件標題或候選章節。
- 一般問題可直接回答；需要外部證據的問題才呼叫檢索器。
- IFRS 17 問題可由 query-only router 判斷檢索，不依賴硬編碼領域名稱。
- 無關問題即使 Embedding 固定返回一個排名第一片段，也會被 Evidence Gate 擋下。

### 狀態

- 已修復並加入自動測試。

## 2026-07-23 - 精確外部事實被誤判為一般常識

### 現象

- 上傳台灣勞動基準法與 NASA Mars 2020 兩份非 IFRS 17 公開資料後，文件解析、切塊與 Embedding 均成功。
- Router 卻把「勞工正常工作時間上限」、「毅力號巡航天數與距離」等精確事實判定為穩定一般常識，直接交給 Qwen 憑模型記憶回答。
- 直接回答的 NASA 距離錯誤；故意選錯文件時也因未進入檢索，無法由 Evidence Relevance Gate 阻止幻覺。

### 根因

1. Query-only prompt 雖要求專門事實走檢索，但沒有明確區分「基礎一般常識」與「看似熟悉、實際需要核對的法律或任務數據」。
2. Qwen 2.5 7B Router 把模型曾看過的法規與 NASA 資訊當成可可靠直接回答的知識。
3. Router 缺少低成本的風險保護層；模型一旦輸出 `needs_retrieval=false`，後續檢索與證據判斷全部被跳過。

### 修正

- Router prompt 明確規定：模型記憶不算外部證據；法律、政策、標準、特定任務、產品、機構，以及精確日期、數值、限制、期限與距離應先檢索。
- 新增 query-only 的確定性保護規則，只看問題文字，不讀文件清單：
  - 明確依賴法規、文件、官方來源或查證的問題固定檢索。
  - 具體主題搭配精確數值、期限、上限、距離、版本等需求時固定檢索。
  - 日期時間、基本算術、寒暄、翻譯與使用者已提供完整文字的處理仍直接回答。
- 未把「勞基法」、「NASA」或任何目前上傳文件名稱寫進 Router；保留不知道語料內容的設計前提。
- 新增 4 個 Router 測試，涵蓋法規、精確任務數據、短的一般常識與含數字翻譯。

### 驗證

- 公開資料端到端案例 7/7 通過：
  - 2 題中文法律問答正確檢索並引用。
  - 2 題 NASA 問答正確檢索，其中中文問英文文件的 BM25 為 0、Embedding 為 0.790427，確認向量檢索真正發揮作用。
  - 2 題故意選錯文件均被判定 `irrelevant / low`，不呼叫 grounded generation，引用數為 0。
  - `2 + 2` 仍走 Direct 路徑。
- Python 測試 47/47 通過；JavaScript/API 測試 10/10 通過。
- 詳細結果：`docs/public-data-rag-validation-2026-07-23.md`。

### 狀態

- 已修復並完成公開資料回歸測試。

## 2026-07-26 - 數字門檻混淆、無關證據誤放行與模糊查詢失真

### 現象

- 「工作滿兩年被資遣」的正確證據是二十日前預告，但 Qwen 回答三十日。
- 連續追問「剛好滿三年」時，Top-1 已明寫三十日，Qwen 仍沿用上一題的二十日。
- 「台北捷運末班車」只命中「資料、時間」等泛用詞，Evidence Gate 卻放行並附上勞動法引用。
- 「公司要我多做一點，這樣合法嗎」被改寫成過度抽象的「公司要求合法性」，找不到工時與加班章節。
- 「今天是幾月幾日、星期幾」未命中既有日期快路徑，浪費一次 Router 模型呼叫。

### 根因

1. 7B 模型在同一片段含多個相鄰區間時，容易交換「以上／未滿」對應的數字。
2. 對話歷史雖已排除舊助理回答，模型仍可能受到上一題數字與主題錨定。
3. Evidence Gate 把所有 BM25 matched terms 等量看待，沒有排除低辨識力詞彙。
4. 模糊口語的 query rewrite 沒有強制保留具體動作，只留下抽象法律意圖。
5. 日期判斷正規式只支援日期或星期單一問法，未涵蓋組合問法與「那」前綴。

### 修正

- 新增 `rag_demo/threshold_evidence.py`，以通用方式解析年／月、以上、未滿、以下等區間；依目前問題與檢索片段的語意重疊選出正確列。
- 命中結構化門檻時直接輸出該列與來源，不再讓生成模型重新選擇相鄰數字；完整公式或金額問題不會誤用上一題門檻意圖。
- RAG system prompt 明定目前問題與本次證據優先，舊對話不是證據；公式題必須完整列出公式。
- Evidence Gate 區分 matched terms 與 meaningful matched terms；「資料、時間、說明」等泛用詞不能單獨放行弱語意片段。
- 弱語意相似度不再因問題寫有「這份資料」就自動視為足夠，無關問答維持零引用。
- Query rewrite 必須保留具體動作並展開自然同義詞，禁止只留下「合法性、規定、資料、要求」等抽象詞。
- 日期快路徑支援「日期＋星期」組合問法與「那今天星期幾」等追問。
- Ollama 生成預設改為 `temperature=0.0`、`seed=42`，仍可由環境變數覆寫。

### 驗證

- Python 單元測試：70/70 通過。
- JavaScript/API 測試：10/10 通過。
- 勞動法規最終端到端驗收：13/13 通過。
- 精準、模糊、無關、連續問答四類的 route、retrieval、answer 與 overall 平均分數均為 1.0。
- 「滿兩年」回答二十日前預告；「剛好滿三年」回答三十日前預告。
- 無關捷運題明確拒答且引用數為 0。
- 模糊加班題改寫後 Top-1 為「正常工時、延長工時與加班費」。
- 日期快路徑約 9–10 ms；結構化門檻題在模型與 embedding 暖機後約 55–118 ms。
- 一般 Qwen 生成題仍約 26–52 秒，現階段主要效能瓶頸是本機 7B 路由與回答生成，不是 BM25、Embedding 或 Rerank。
- 最終原始結果：`RAG_Evaluation/2026-07-26/labor_rag_eval_raw_final_complete_20260726.json`。

- 已修復並完成完整回歸測試。

## 2026-07-26 - Canonical server-side RAG Pipeline 與 Evidence 信任邊界

### 問題

- `/api/ask` 會接受瀏覽器傳入的 `contexts`、BM25/Embedding/Rerank 分數與 `retrieval_decision`。
- 客戶端可偽造高分文件或要求跳過檢索，使回答與引用不再由伺服器控制。
- Web、CLI 與批次評測使用不同問答路徑，歷史測試結果不能直接代表正式 API。
- Citation 回傳欄位固定取前四個 Context，可能與回答實際標示的來源 Rank 不一致。

### 修正

- 新增 `rag_demo/rag_pipeline.py`，集中執行日期工具路由、Query Router、Hybrid Retrieval、Evidence Gate、Grounded Generation、Conversation Persistence 與 Citation 建立。
- 新增 `RagPipelineRequest`，正式輸入只包含問題、allowlisted model、profile、`source_ids`、Top-K 與 conversation ID；資料型別沒有 Context、Score 或 Route Decision 欄位。
- `/api/ask` 改成只建立 canonical request，再呼叫 `RagPipeline.run()`；客戶端夾帶的 Evidence 與路由資料會被忽略。
- 前端 Query Schema 升級為 `rag-agent-query-v2`，不再把檢索 Context 或路由決策回傳給回答 API。
- 模型新增 server-side `RAG_ALLOWED_MODELS` allowlist，未核准模型回傳 HTTP 400。
- `run_id` 改成 UUID；Citation 綁定同一個 `run_id` 與 Context 內容 SHA-256。
- Citation 改依回答中的實際 Rank 標記建立，不再固定取前四個 Context；無效 Rank 會產生 Grounding Warning。
- `python3 -m rag_demo.query` 預設改走 canonical Pipeline，保留 `--legacy` 供歷史比較。
- 新增 `scripts/run_canonical_pipeline_eval.py`，批次評測與正式 API 共用 Pipeline，Artifact 保存 commit、dirty 狀態、設定、逐題結果與時間。
